Backup & Restore — Help

TunerControl keeps your data in one of two places: on the TunerControl server (when the pages are served from it), or in this browser (IndexedDB) when they aren't. The line at the top of the page says which. A backup is one JSON file with everything stored there, and it can be restored into either kind of storage.

What a Backup Holds

  • Every tune imported into the M1 Config Viewer, with its original .m1pkg file.
  • Your I/O resource names and labels.
  • The Tuning History (saved VE, transient fuel, knock and fuel pressure runs).
  • Every harness with all of its revisions, harness systems with their joins and CAN networks, and the harness pictures.
  • This browser's page settings (remembered choices on the tool pages).

It does not hold your log files (they are never stored — you open them from disk each time) or the server's access token.

Making a Backup

  1. Check Stored now to see what is there.
  2. Click Download backup. The browser saves the file; the page shows its size and contents.
  3. Keep it somewhere other than the server or this computer.
Browser storage can disappear. Clearing site data, a private window or a new browser profile starts empty. Without the server, back up after importing tunes or saving harnesses.

Restoring

  1. Click Choose backup file… and pick the JSON file. The page shows when and where it was made and what it holds.
  2. Click Restore (or Cancel).

Restoring adds what isn't stored yet and never deletes. Anything already stored with the same id is left as it is, so restoring the same file twice is safe and a restore can't roll back newer work. Resource names, labels and page settings are set from the backup. When it's done, the page says how many of each were added.

Backups made with the M1 Config Viewer's older Export backup restore too; they hold only M1 Config Viewer data (tunes, and names and labels in later versions).

Common Uses

Moving from browser storage to the server

Open this page without the server and download a backup, then open it from the server and restore it. Everything keeps its id, so harness systems still point at their harnesses.

Recovering a lost server

Set up the server again (see server/README.md), open this page from it and restore the latest backup. The same file also restores into a browser, so the data can be used before the server is back.

A second computer or browser

Restore the backup there. With a server you don't need to: every browser that opens the pages from the server sees the same data.

On the server: the same backup is available at GET /api/backup (and restored with POST /api/backup), so it can be scheduled. The SQLite database file itself can also be copied with sqlite3 … ".backup …" — see server/README.md.
