Charge Cooling Gain — Help

The charge cooling gain represents how much the injected fuel cools the intake charge before combustion. It directly affects the air density calculation in the MoTeC airflow model.

What is Charge Cooling?

When fuel is injected, it absorbs heat from the intake air as it evaporates (latent heat of vaporization). This cooling effect reduces the charge temperature below what the IAT sensor reads. The charge cooling gain tells MoTeC how many degrees Celsius to subtract from the IAT reading to compute the actual charge temperature entering the cylinder.

The equation (simplified): Charge Temperature = IAT - (Charge Cooling Gain × fuel_factor)

If the gain is too low, the ECU overestimates charge temperature → underestimates air density → delivers too much fuel (runs rich when you command a richer target). If too high, the opposite (runs lean when commanding rich).

Prerequisites

  1. VE table must be calibrated — at steady state (1.0 lambda target), actual lambda must match target. If VE is wrong, charge cooling results will be invalid.
  2. Closed loop must be DISABLED — the CL correction will mask charge cooling errors.
  3. Time constants zeroed — set Engine Charge Temperature Time Constant = 0, Port Temperature Time Constant = 0, Correction Factor = 0.
  4. Engine must be warm — coolant >80°C for consistent results.
Critical: If you run this test with closed loop enabled, the CL correction will compensate for charge cooling errors and you'll get incorrect results. Disable CL before the step test.

Test Procedure

  1. Warm the engine fully (coolant >80°C)
  2. Disable closed loop lambda correction (set max/min to 0%)
  3. Zero the charge temperature time constant and correction factor tables
  4. At idle, verify lambda tracks 1.0 target accurately (VE must be correct)
  5. Change target lambda from 1.0 to 0.9 in the target lambda table
  6. Wait 3-5 seconds for lambda to settle
  7. Change target lambda back to 1.0
  8. Wait 3-5 seconds for lambda to settle
  9. Repeat 2-3 times for multiple data points
  10. Log the session and load it into this tool
Tip: You can also test at different lambda targets (1.0 → 0.85, 1.0 → 1.05) to verify the gain works in both directions. The tool detects any lambda target step change >3%.

Interpreting Results

Lambda tracks target accurately (error <0.5%)

Charge cooling gain is correct. No adjustment needed.

Actual lambda is RICHER than target (negative error)

Example: target = 0.9, actual = 0.88. The ECU is delivering too much fuel. The charge cooling gain is too low — the ECU underestimates charge cooling, overestimates charge temperature, and over-fuels as a result. Increase the gain.

Actual lambda is LEANER than target (positive error)

Example: target = 0.9, actual = 0.93. The ECU is not delivering enough fuel. The charge cooling gain is too high — the ECU overestimates charge cooling, underestimates charge temperature, and under-fuels. Decrease the gain.

Expected Values by Fuel Type

  • Petrol (E0-E10): 10–25°C (MoTeC default: 13°C)
  • E85: 25–50°C (ethanol has ~3× the latent heat of petrol)
  • Pure Ethanol: 40–70°C
  • Methanol: 50–90°C

Higher ethanol content = more cooling effect = higher gain value needed.

IAT Sensor Considerations

The charge cooling gain is indexed by Inlet Air Temperature. At different IAT values, the cooling effect may change slightly. For most applications, a single value works well. If you tune at 30°C IAT but drive in 5°C conditions, the same gain should still be accurate.

Heat soak: If your IAT sensor is mounted in the intake manifold (not the airbox), it can heat-soak when the engine is idling with no airflow. This gives artificially high IAT readings and can make the test less accurate. Best results come from testing immediately after a short drive when the IAT sensor is reading true ambient-influenced temperatures.

Troubleshooting

No step events detected

The tool looks for the "Fuel Mixture Aim" channel changing by >3% between adjacent samples. If your target lambda changes gradually (ramp) rather than as a step, the tool won't detect it. Make abrupt changes in the target lambda table.

Results seem wrong / suggested gain is outside expected range

Most common causes:

  • Closed loop was still active (check that CL trim is 0% in the log)
  • VE table is not calibrated (lambda doesn't track 1.0 at steady state)
  • IAT sensor heat soak giving bad readings
  • Not enough settle time between steps (lambda still moving when measured)
