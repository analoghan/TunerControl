M1 Config Viewer — Help

Reads MoTeC M1 Tune packages (.m1pkg) directly — no export step — so you can browse every parameter, table, I/O assignment and calibration selection, and see exactly what changed between two saved versions of a tune. The viewer only reads packages; it never changes them.

Importing tunes

  1. Save the tune in M1 Tune. Each save is a .m1pkg file (M1 Tune names them with a long ID, e.g. A9FCB7F0-….m1pkg).
  2. Click Choose Files and select one or more packages. Each one is read and added to the Tune History.
  3. Importing the same file again is detected and skipped — a package is identified by its exact contents, not its file name.

The viewer reads the working copy of the calibration in the package — the values you were tuning when you saved, the same values M1 Tune shows.

Tip: Import every saved version (V54, V55, …) to build up a history you can compare.

Where tunes are stored

The line under the import button says where imported tunes are kept:

MessageMeaning
Stored on the TunerControl serverThe page was opened from a TunerControl server. Every browser that uses that server sees the same tunes, and the data can be queried with SQL (see server/README.md).
Stored in this browser onlyTunes are kept in this browser's storage. Another browser or computer won't see them — use backups to move them.
Kept only until the page is closedThe browser blocks storage (e.g. a private window). Nothing is saved.

When the package reader improves, tunes imported earlier are re-read automatically from their original files, so they pick up the improvements without importing them again.

Tune history and comparing

The Tune History table lists every imported tune with its name, save time, firmware version and the last note in its save comments. View shows that tune below; Delete removes it from the history.

Comparing two versions

  1. Pick the older tune in the first Compare list and the newer one in the second.
  2. Click Compare. The Changes tab lists everything that differs:
  • Parameters — old → new value.
  • Tables — each changed cell with its axis breakpoints (e.g. 3000 rpm, 80 kPa), including changed axis sites.
  • I/O assignments — the resource and pin before and after.
  • Calibration selections — sensor, injector and fuel calibrations chosen from the M1 Tune library.
  • Save notes added since the older version.

Browsing parameters and tables

The tabs group the tune: Calibrations (library selections), Firmware Features, Driver Switches, Engine Setup, Vehicle Setup and All Parameters. Use the search box to filter by name and the All / Parameters / Tables / I/O Resources buttons to filter by type.

Tables show their size (e.g. 20 × 24, or 20 × 24 of 36 × 24 when not every axis site is used). Click Show to expand the grid with its axis breakpoints.

Following settings

Click a setting's name to open its group (e.g. Driver.Switch 8), or a value shown as a link to open what it points at. The Follow window shows:

  • Referenced by — every setting elsewhere that points at this group or resource: an enum value naming it (Brake Switch Index = Driver Switch 8), an I/O assignment, or a table axis reading its channel (Fuel Mixture Aim Main, Z axis: Driver Fuel Mixture Aim Main Switch).
  • Uses — what the group's own settings point at (Input Resource → FIRMWARE5).
  • Settings — the group's values, with their links, and the groups inside it.

For an I/O resource such as FIRMWARE5 it lists every assignment and every enum value that selects it — e.g. the driver switch reading it and the CAN receive signal writing it. Keep clicking to follow the chain; the trail at the top shows the path (Brake.Switch.Index → Driver.Switch 8 → FIRMWARE5 → CAN.Receive.Custom.Message 1.Signal 2), Back steps back, the In … line opens the parent groups, and Find shows a setting in the All Parameters table.

Links are worked out from the names in the package: an enum value links when it names a group (spacing and dots ignored, or its words in order, e.g. Driver Keypad Button 7 → Driver.CAN Keypad.Button 7) or a resource (Firmware 5 = FIRMWARE5). Values that name nothing in the tune, such as On or a sensor type, are not links.

Your labels

Settings such as auxiliary inputs and outputs only say what they are, not what you use them for. Open one in the Follow window (click its name) and press Add label to give it free text — e.g. Auxiliary Output 3 = intercooler pump relay or FIRMWARE5 = brake light from chassis CAN. The label then shows as a green tag wherever that setting or resource appears: next to its settings in every table, on values that point at it, in the Follow window and on the Firmware I/O tab. A label on a group also shows on the groups inside it.

Labels belong to the setting's name, not to a tune, so they carry across tune versions and firmware revisions until you edit or remove them (a firmware that renames the setting would need it again). The search box finds labels too, and the My Labels tab lists them all, including any for settings not in the tune you are viewing. Labels are stored with your I/O resource names — on the server, or in this browser — and are included in Export backups.

Firmware I/O channels

The Firmware I/O tab lists the ECU's virtual I/O channels FIRMWARE0–FIRMWARE31. For each it shows what writes it — usually a CAN receive custom signal, with its bus, CAN ID, start bit, length and scaling — what reads it (a driver switch, rotary or counter switch, or a sensor input whose resource is that FIRMWARE channel) and what the reading input is then used by (e.g. FIRMWARE5 ← CAN Message 1 Signal 2 → Driver Switch 8 → Brake Switch). Tick Show unused channels for all 32; the search box filters the rows. Every name opens the Follow window.

Value history across versions

With two or more tunes imported, you can see how any value changed over every saved version:

  • Parameters and I/O assignments — click History next to the value.
  • Table cells — expand the table with Show and click a cell.
  • Changes tab — click a changed cell's location, or history next to a changed value.

The history lists every tune (newest first) with its save time, the value in display units and the change from the previous version, with a chart for numbers. A tune that doesn't have the parameter shows —.

Units

Packages store values in base units (deg/s, Pa, seconds, ratios). The viewer converts them to the units M1 Tune shows — rpm, kPa, ms, %, °C — so values match what you see in M1 Tune.

Angles are shown in M1 Tune's units: dBTDC (before top dead centre), dATDC (after top dead centre), dRTD (degrees retarded) and dADV (degrees advanced).

I/O resources, names and pins

A package stores each I/O assignment as resource IDs, not as the name M1 Tune shows. The viewer turns the IDs it knows into names — AVI2, UDIG7 Hybrid B, Direct Injector 1A-, E888 Output 8, PDM Byte 0, Mask 01, FIRMWARE4 — and shows the connector pin in the Pin column:

M142 pin C15 — pin C15 on the ECU's connector C (from the M142 datasheet)

E888 pin A32 — pin A32 on the E888 expander's connector A (from the E888 manual)

M142 pin A06 (+ A07) — direct injector: the − pin M1 Tune assigns, then its + pin

M142 pin C18 / C01 — bridge output: both half-bridge pins

PDM and FIRMWARE resources have no physical pin, so their Pin column is empty.

Naming an unknown resource

If a value shows only raw IDs (e.g. 0x6554), check the assignment in M1 Tune, click Name next to it and enter the name M1 Tune shows. The name applies to every tune and item using that assignment on the same ECU hardware, and is also used by the Harness Builder.

Tip: Enter the name as M1 Tune or the datasheet writes it — e.g. UDIG2, Universal Digital Input 2, Half Bridge Output 4, Knock Input 1, E888 AVI3 — and the pin is filled in automatically.

Backups

Export backup saves every imported tune and your resource names to a JSON file. Restore backup loads one — use it to move tunes to another browser, or from browser storage onto a TunerControl server. Tunes restored from a backup don't include their original files, so they aren't re-read when the package reader improves; re-import the .m1pkg files if you still have them.

Used by other tools

  • VE Table Tuning reads Engine Efficiency Main from a .m1pkg or straight from a tune stored here.
  • Transient Fuel Analyzer reads Fuel Film Primary and its scale, offset and time constants the same way.
  • Harness Builder compares tunes stored here with your wiring harness, pin by pin.

When you choose a log in the VE or Transient Fuel tool, it suggests the stored tune that was most likely in the ECU when the log was recorded: the latest tune from the same ECU (serial number) saved before the log started. Logs carry the ECU serial and start time in their header (.ld) or file name (…#30924_20260611_173221…). Choosing a file or another tune yourself always wins.

Troubleshooting

  • "Could not read" on import — make sure the file is an M1 Tune package (.m1pkg), not an exported CSV or a log. Packages from other M1 firmware or hardware may use layouts the viewer hasn't seen.
  • Tunes disappeared — browser storage is per browser and per address. Opening the page from a different address (or a private window) shows a different, empty history. Use a TunerControl server, or Export/Restore backup.
  • An I/O value shows only IDs — the resource isn't known yet; name it with the Name button.
  • A value looks wrong — compare it with M1 Tune and note the item name and unit; the conversion for that unit may need adjusting.
